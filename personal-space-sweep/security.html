Personal Space Sweep for Confluence — Security Policy

Security

What this policy covers

This is the security policy for Personal Space Sweep for Confluence, a Forge app that lists the personal spaces on a Confluence Cloud site, marks the empty ones and archives them in bulk. It covers version 1.0.0 and every later version published under the same app key, ua.pp.maxpetrov.personal-space-sweep.

The app is written and maintained by one person, Max Petrov. There is no second office, no subcontractor and no sub-processor: the whole of it is the Forge app you install.

Where the app runs, and what leaves your site

The app runs entirely inside Atlassian Forge, on Atlassian's own infrastructure, inside your tenant. Its manifest declares no permissions.external block, no remotes entry and no remote hostname, it opens no network connection of its own, it exposes no remote REST API and it registers no web trigger. It therefore has no internet-facing attack surface outside Atlassian, and no data of yours leaves Atlassian.

There is no vendor server to breach, no vendor database to leak and no vendor log to subpoena, because none of the three exists. Authentication is Forge's own; the app holds no credential, no API token and no secret of its own, and it asks you for none.

What the app stores

Nothing. Version 1.0.0 persists no customer data at all: it reads the space list and the page counts when you open the administration page, renders them, and keeps nothing once the page is closed. The app's own test suite asserts that the shipped code performs zero storage operations.

The manifest declares the storage:app scope even so. That is deliberate and it is not a hidden store: adding a scope after release pushes every existing customer through a site-admin consent step, so the scope is declared in the first version and left unused until a feature needs it. If a later version begins to store something, this policy and the privacy policy say what, before that version ships.

What the app can reach, and why

Eight scopes, each of them the narrowest one that does the job. Six are read-only or status-only; two are the actions the product exists to perform.

  • read:space:confluence - Reads the list of spaces on the site so the page can show which of them are personal spaces, with their keys. Without it the app has nothing to list.

  • read:space-details:confluence - Reads each space's type and status, which is what separates a personal space from a global one, and a current space from one that is already archived.

  • read:content.metadata:confluence - Reads page metadata for the emptiness count. The app counts pages; it never reads the body of a page and it stores no page content anywhere.

  • read:page:confluence - Lists the pages in a space so the scan can report zero or not zero. It is the narrowest read the v2 pages endpoint accepts for that count.

  • write:space:confluence - Archives and restores a space. This is the reversible action the product is built around: an archived space keeps its content and comes back unchanged.

  • write:space.permission:confluence - Confluence requires it alongside the space write when a space changes status. The app never edits a permission, never adds a grant and never removes one.

  • delete:space:confluence - Deletes a single space, and only after an administrator types the space key into a confirmation field. No bulk path in the app can reach this call.

  • storage:app - Forge app storage, declared in version 1.0.0 because adding it later pushes every existing customer through a site-admin consent step.

Destructive actions, stated plainly

Archiving is the action the product is built around and it is reversible: an archived space keeps its content and comes back unchanged when it is restored.

Deleting a space is not. delete:space:confluence removes the space and its pages permanently — Confluence provides no trash and no recovery for a deleted space. Deletion cannot be undone: not by the app, not by its author, and not by Atlassian support.

Because of that, delete is single-target only. It is reachable from no bulk path, it cannot be applied to a selection, and it runs only after an administrator types the space key by hand into a confirmation field that must match exactly. Deletion of the space you are signed in as is refused outright.

How this app is secured

  • Report a suspected vulnerability in this app to support@maxpetrov.pp.ua with the words SECURITY REPORT in the subject. Reports are acknowledged and triaged by the person who wrote the code.

  • The app runs entirely inside Atlassian Forge. Its manifest declares no permissions.external block and no remote hostname, it opens no network connection of its own, it exposes no remote REST API and it runs no web trigger — so it has no internet-facing attack surface outside Atlassian.

  • The app collects no Atlassian credential and no API token from anybody. It authenticates as the app through Forge and holds no secret of its own.

  • Authorisation is enforced in the app's own resolver code, not by hiding a control: the destructive routes re-check before they call Confluence, and Confluence itself refuses a caller who lacks the right on the space.

  • The one destructive, irreversible route — deleting a space — is single-target only, is reachable from no bulk path, and is gated behind a confirmation string the administrator types by hand.

  • A fix for a confirmed vulnerability ships as a new Forge version; Forge apps on Atlassian cloud are upgraded by Atlassian, so there is no customer-side patch step.

Reporting a vulnerability

Email support@maxpetrov.pp.ua with the words SECURITY REPORT in the subject. The report reaches the person who wrote the code; nobody else reads that mailbox.

One person reads that mailbox — the one who wrote the app — and every request gets a first reply within two business days, Monday to Friday. That is the window a part-time maintainer can hold every week rather than on a good one; most replies land sooner.

Please include the app version, the Confluence site you saw it on and the steps to reproduce. A confirmed vulnerability ships as a new Forge version; Atlassian upgrades Forge apps on Cloud itself, so there is no patch for you to install and no action for your administrators to take.
