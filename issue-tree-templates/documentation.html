Issue Tree Templates for Jira - Documentation

Documentation

Overview

Some teams do the same shaped work over and over. A client is onboarded, a release goes out or an incident gets a postmortem. Every time, somebody rebuilds the same epic, the same stories and the same sub-tasks by hand, or clones an old epic and cleans up what came with it.

Open any epic, choose Save as issue tree template, and the app captures it: child items, sub-tasks, their field values and the links between them. No shadow project, and capture only ever reads.

Then create the whole structure in any project in one click, filling in variables such as a client name, a start date or an assignee as you go. Or let Jira Automation run the Create issue tree from template action, even on a schedule.

Before anything is created, preflight reports every field as carried over, remapped, skipped or blocked, with the fix. If anything is blocked, nothing is created.

No epic to start from? One button builds a starter template from your own project's issue types.

Highlights

  • Turn any epic into a reusable template - Choose Save as issue tree template from a work item's menu. Its child items, sub-tasks, field values and the links between them become one template, and nothing in Jira is changed.

  • No half-built epics to clean up - Before anything is created, preflight checks the target project and shows each field as carried over, remapped, skipped or blocked, with the fix. If anything is blocked, nothing is created at all.

  • One template library for every project - Keep onboarding, release and incident structures in one library that works in any project. Draw links between work items, drop field values you do not want, and see which templates teams actually use.

Known limitations

  • No template picker inside Jira's own Create dialog. You start from the app's page, or from the work item you want to template.

  • A captured tree is limited to 200 work items and four levels deep.

  • Attachments are not copied.

  • There is no undo. Preflight is designed to make one unnecessary; if a run does fail part-way, the app lists exactly which items were created.

Getting help

Email support@maxpetrov.pp.ua and we will reply. Include the template name, the target project key, and what preflight reported. If a run was blocked, paste the blocked line: it names the field and the fix. If work items were created but look wrong, the issue type names in the template are the first thing to check, because they differ between company-managed and team-managed projects.
